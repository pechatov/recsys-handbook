# 2.2. Данные и фичи

:::note[Черновик]
Это заглушка: ниже зафиксирован план содержания лекции. Текст будет написан
позже.
:::

## Что должно быть в лекции

- Какие данные порождает продукт: события, показы (impressions), клики,
  сессии, покупки/досмотры, «негативный» фидбек.
- Логирование как фундамент системы: что и как логировать, чтобы потом можно
  было учиться; почему обязательно логировать показы, позиции, request-id,
  версию модели и состав выдачи.
- Устройство фичей: пользовательские, айтемные, контекстные, кросс-фичи;
  счётчиковые и агрегатные фичи с разными окнами.
- Point-in-time correctness: фичи «на момент события» и утечки будущего через
  фичи.
- Feature store: зачем нужен, offline/online-консистентность, проблема
  training/serving skew.
- Realtime-сигналы: сессионные фичи, свежие взаимодействия, стриминговые
  счётчики.
- Негативы и отсутствующие данные: показ без клика, пропущенный показ,
  censored feedback, задержанные конверсии.
- Качество данных: боты, дубли событий, потерянные логи, скачки распределений;
  базовый мониторинг входных данных.
- Практика: собрать схему логов и набор фичей для сквозного примера без
  утечек будущего.
