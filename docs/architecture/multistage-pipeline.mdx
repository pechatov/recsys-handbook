# 2.1. Многоступенчатый пайплайн рекомендаций

:::note[Черновик]
Это заглушка: ниже зафиксирован план содержания лекции. Текст будет написан
позже.
:::

## Что должно быть в лекции

- Почему нельзя прогнать тяжёлую модель по всему каталогу: миллионы айтемов,
  бюджет задержки в десятки миллисекунд, стоимость инференса.
- Каскадная архитектура: кандидатогенерация → ранжирование → реранкинг; зона
  ответственности и вычислительный бюджет каждого уровня.
- Воронка кандидатов: миллионы → тысячи → сотни → десятки; trade-off «полнота
  vs точность vs скорость» на каждом шаге.
- Разбор реальных систем по публикациям: YouTube, Instagram, Pinterest,
  Alibaba — общие паттерны и различия.
- Согласованность уровней: как кандидатогенерация ограничивает потолок
  качества ранкера; как оценивать каждую стадию отдельно.
- Где в каскаде живут бизнес-правила, фильтры и продуктовые ограничения.
- Вариации и вырожденные случаи: retrieval-only системы, одноуровневые
  системы для маленьких каталогов, end-to-end подходы.
