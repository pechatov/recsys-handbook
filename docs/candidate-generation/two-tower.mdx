# 3.3. Двухбашенные модели

:::note[Черновик]
Это заглушка: ниже зафиксирован план содержания лекции. Текст будет написан
позже.
:::

## Что должно быть в лекции

- Ограничения матричной факторизации: нет фичей, нет холодного старта —
  мотивация добавить контент и контекст в модель.
- Архитектура two-tower: user tower и item tower, дот-продукт или косинус как
  скор; какие фичи кладут в каждую башню.
- Обучение как extreme classification: softmax по каталогу, sampled softmax,
  in-batch negatives.
- Коррекция смещения сэмплирования (logQ correction), температура, добыча
  hard negatives.
- Фундаментальное ограничение: позднее связывание башен — почему кросс-фичи
  user × item сюда не положить, и что с этим делает ранкер.
- Сервинг: предрасчёт item-эмбеддингов + ANN-индекс, онлайн-расчёт
  user-эмбеддинга.
- Соседние семейства нейросетевого retrieval: факторизационные машины и
  автоэнкодеры (MultVAE) — где они конкурентоспособны.
- Разбор классики: YouTube DNN retrieval и более свежие индустриальные
  публикации.
- Практика: обучаем two-tower и сравниваем recall с матричной факторизацией.
